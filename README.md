# Crack-shot · 大麦个人抢票辅助

通过 ADB + uiautomator2 在**自己的安卓真机、自己的账号**上辅助抢票：人工做好全部准备并停在演出详情页，脚本只在开票瞬间轮询"立即预订"按钮 → 点击 → 选票档 → 确定 → 提交订单；失败/售罄页面自动退出重试；**验证码一律停下交给人工**。

> ⚠️ 仅限给自己抢票的自用场景。自动化购票违反大麦用户协议，存在账号被风控（弹验证码、限购、封号）的风险；多账号、代抢、转卖属违法，本项目不做、也严禁用于此类用途。

## 设计原则

- **自动化窗口最小化**：只在开票前后约 90 秒内动作，其余时间账号完全是正常人工使用。
- **识别与点击分离**：uiautomator2 只做"看"（找按钮、判断状态），关键点击走裸 `input tap`，设备上无常驻自动化服务参与点击。
- **全时序抖动**：轮询间隔、点击间隔、重试退避全部随机化，无固定毫秒节奏。
- **硬边界**：不碰验证码、不碰支付（下单成功后人工支付）、点击全局限速、尝试次数硬上限。

## 安装

```sh
cd "/Volumes/Mac SSD1/projects/Crack-shot"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

电脑需有 adb（本机在 `~/.local/bin/adb`，自动探测；也可在 tasks.yaml 配 `adb_path`）。手机：开启开发者选项 + USB 调试，连电脑并授权；首次运行 doctor 会通过 uiautomator2 在手机上安装 atx-agent（普通应用，用完可在设置里卸载）。

## 使用流程

**抢票日之前（人工，一次性）：**
1. 大麦 App 保持登录；「我的-观演人」添加好观演人；
2. App 内搜索目标演出，进入详情页，确认场次、票档文字（如"¥688"）；
3. 复制 `tasks.example.yaml` 为 `tasks.yaml`，填好任务（演出关键词、开票时间、票档优先级）；
4. 手机连电脑，运行 `python main.py doctor` 自检。

**抢票日当天：**
```sh
python main.py list                          # 确认任务和倒计时
python main.py probe                         # 手机停在详情页时，确认识别正常
python main.py watch                         # 可选：实时看按钮状态识别（不点击）
python main.py run --task chenxiaochun-quzhou
```

人工部分：开票前几分钟打开大麦、停在目标演出详情页、保持亮屏。脚本会倒计时 → 预热校验（页面不对会语音报警）→ 开票瞬间自动执行。出现验证码、观演人未预填、排队超时等情况会**停下并语音通知**，按手机提示人工处理。

**演练（强烈建议先做一次）：**
```sh
python main.py run --task xxx --now --dry-run   # 立即进入循环但只识别不点击
python main.py watch                             # 观察按钮状态翻转识别是否灵
```

## Web 后台（多设备任务管理）

```sh
./backend.py start              # 后台启动，打开 http://127.0.0.1:8780
./backend.py status             # 查看运行状态
./backend.py stop               # 停止后台
```

脚本使用项目的 `.venv`，启动日志写入 `var/backend.log`。有任务正在运行时，请先在后台停止任务或等待它结束，再执行停止脚本。

后台能力：

- **任务管理**：新建任务先保存为草稿。绑定设备后点「校准」，后台打开目标站详情页，读取页面开售时间；核对后点「确认开抢时间并排程」。默认提前 5 分钟启动页面守护，开售后检测到可购按钮即点击。
- **定时演练**：在独立草稿上点「定时演练」，设定测试时间。运行日志会记录调度启动、进入详情页和到点核对结果。演练会操作搜索和页面导航，不点击购买或提交订单。
- **正式运行录屏**：预热开始时录制手机画面，任务结束后在「运行记录 → 详情」里回放或下载无声 MP4。录屏保存在 `var/recordings/`。需安装 [scrcpy](https://github.com/Genymobile/scrcpy/blob/master/doc/macos.md)，程序会查找项目内的 `var/tools/scrcpy/scrcpy` 或系统 PATH，也可用 `CRACKSHOT_SCRCPY` 指定路径。录制失败会写入运行日志。
- **搜索和守护**：支持首屏多城方格和竖排结果，不下滑找。连续两次未能确认目标详情页会停止并通知人工。
- **截图提取录入**：任务表单里上传大麦截图，调用**本地 Ollama 视觉模型**（如 qwen3-vl）提取演出名、票档、开售提示并预填表单，时间等字段仍需人工确认；需本机运行 Ollama 并装好视觉模型；
- **账号/设备管理**：注册 ADB 设备并绑定账号标注（谁的手机），在线状态实时显示，未注册的在线设备一键注册；
- **多设备并发**：调度器每 2 秒扫描到期任务（开票前 prewarm 分钟），每台设备同时最多执行一个任务，设备被占用的任务标记「设备冲突」并告警；错过开票窗口的任务自动标记失败，不会反复触发；
- **状态与结果**：任务状态机（草稿→校准待确认→待执行→预热中→抢票中→成功/需人工/失败）、每次运行的事件时间线、关键节点截图证据在 `var/evidence/`。

定时执行期间请保持后台运行、电脑唤醒、手机通过 USB 连接且无需解锁验证。后台不会替你解锁手机或处理验证码。

账号-设备-任务的绑定模型面向**本人及家人各自账号自用**的场景设计（每台手机一个真实账号、抢自己的票）；不做批量账号管理、自动登录或任何群控能力，严禁用于代抢、转卖。

CLI（`run/probe/watch`）继续可用，与 Web 后台互不干扰；CLI 走 `tasks.yaml`，Web 走 `var/crackshot.db`。

## 状态机

```
预热(校验页面) → 详情页轮询按钮[即将开抢/缺货 → 立即预订]
  → 到开票时刻且检测到可购按钮才点击
  → 点击 → 选票页(按优先级点票档, 跳过缺货) → 确定
  → 确认订单页(核对观演人已预填) → 提交订单
  → 成功=通知人工支付 | 排队=等待 | 失败弹窗=关闭并返回详情页重试
  → 验证码=停止交人工
```

- 页面识别基于关键词（`buy_texts`/`wait_texts`/`error_texts` 等均可在任务配置覆盖），大麦改版导致文案变化时改配置即可；
- 识别采用「一次层级 dump + 本地关键词匹配」（250ms 快照共享），避免每个关键词一次 USB 往返；
- 票档匹配是"选票页价格文本包含"（如配置 `688` 匹配 `¥688`），命中行内含"缺货"则自动试下一优先级；
- 日志在 `var/logs/`，关键节点截图证据在 `var/evidence/<任务名>/`，Web 数据库在 `var/crackshot.db`。

## 已知限制

- 页面关键词基于 2026-11 版大麦 App（详情页/选票浮层/确认订单页），**尚未真机全流程验证**——首次使用务必 `--dry-run` 演练并核对 `probe` 输出；
- "在线选座"类演出是选座地图流程，不在支持范围内（默认票档文本匹配不会误点）；
- 提交订单后的排队页、风控弹窗形态多样，脚本一律保守处理：识别不了就交人工。

## 目录

```
main.py            入口（serve 启动 Web 后台）
crackshot/
  config.py        任务配置（tasks.yaml 加载与校验）
  adb.py           adb 封装（探测/点击限速/截图/前台检查）
  device.py        uiautomator2 封装（一次 dump + 本地关键词匹配）
  pages.py         页面状态识别（详情/选票/订单/排队/成功/失败/验证码）
  grabber.py       抢票状态机（开票时刻、可购按钮、票档及订单状态）
  scheduler.py     定时调度（预热校验/倒计时/紧轮询）
  notify.py        macOS 通知（弹窗+声音+语音）
  timeutil.py      时间与抖动
  web/
    app.py         FastAPI REST API + 静态页托管
    db.py          SQLite（账号/设备/任务/运行/事件/设置）
    runner.py      RunManager 多设备并发调度
    extractor.py   Ollama 本地视觉模型截图提取
    static/        单页前端（原生 JS）
tasks.example.yaml CLI 配置示例
var/               日志、证据、数据库（不提交）
```
